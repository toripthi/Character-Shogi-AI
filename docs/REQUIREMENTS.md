# 要件定義書：人間らしい級位者を再現する将棋AI（仮称 character-shogi-ai）

> このドキュメントは、迷ったときに戻ってくる基準。実装の都合で要件を曲げたくなったら、まずここを読み返す。

---

## 1. 目的と背景

### 1.1 課題感
- かつてFLASHの「ハム将棋」が初心者の壁として存在した（2007〜2020）。
- ハメ手で簡単に倒せ、同じ棋譜で同じように勝てる。ハメ手なしの純粋な力戦ではアマ4級程度の棋力。
- **「ハメ手以外で、わかりやすく定量的に測れるNPC」がない。**

### 1.2 既存の将棋AI初心者モードへの不満
| 不満 | 人間の初心者の実態 |
|---|---|
| 飛車を簡単に見捨てる（歩と同等に扱う） | 「へぼ将棋、王より飛車を可愛がり」。自玉が危なくても飛車を逃がす |
| 定跡を忘れさせて力戦してくる | 現代の初心者は定跡を40手近くなぞる。危険でも美濃・矢倉を組もうとする |
| 詰みの読みが深さで決まる（11手詰＝難問扱い） | よくある型（美濃崩し等）は長手数でも即読める。逆に珍しい三手詰は時間がかかる |
| 負け筋で意味のない王手を連発する | 初心者でもやらない。AIは「詰みまでの手数が伸びる」ため選ぶ |

### 1.3 目的
**棋力を調整できる「人間らしい級位者」NPCを作る。** 評価関数・定跡・探索の偏りで棋風（攻め／守り／戦法）を表現する。

## 2. ゴール（完成の定義）

次の定量・定性の**両方**を満たしたら完成。

### 2.1 定量（棋力の校正）
- ぴよ将棋の特定の級との勝率が4〜6割に収まる設定値を、級ごとに見つける。
- 設定値（探索深さ・margin・slip率など）と級の対応表を記録する。

### 2.2 定性（チェックリスト）
作者が対局し、次を確認して「こんな感じ」と思えること。
- [ ] 飛車が狙われたら、自玉が危なくても逃がそうとする
- [ ] 囲い（美濃・矢倉）を、状況に合わなくても組もうとする
- [ ] 序盤は定跡をなぞり、毎回同じ展開にならない
- [ ] **負け筋で、狙いのない王手を連発しない**（§4.1）
- [ ] 攻め屋は前のめりに攻め、倒れ方に味がある
- [ ] ハメ手で同じように勝てない
- [ ] 遠くにある飛・角の利きを、級に応じた頻度で見落とす（目の前の駒は見落とさない）（§4.7）

## 4. 人間らしさの要件

### 4.1 【必須・最重要】無駄王手の排除
**これが満たせないなら、このプロジェクトの意味がない。**

**現象**：負け筋の局面で、探索が「王手をすると詰みまで遠くなる」という理由だけで王手を連発する。
- 例①：歩を5枚持ち、相手玉の頭に歩を打つ→取られる、を5回繰り返して持ち駒が尽きる
- 例②：歩を打つ→玉が引く→と金にして同玉、を繰り返し、玉が上下するだけで負ける

**方針：王手は許可制**
王手を「手数が伸びる」理由では選ばせない。次のいずれかを満たす王手だけを、候補として許可する。
1. 王手と同時に駒得がある（王手飛車取りなど）
2. 相手が応手を間違えれば、こちらに詰みが生じる筋が実在する

許可されない王手は、候補から除外する。全ての候補手が不許可になる場合は、元の候補列をそのまま使う。

**段階的実装**
| 段階 | 内容 |
|---|---|
| 簡易版（MVP必須） | 王手後、相手の応手を全て試し、こちらの次の1手で「駒が取れる」か「詰みがある」かを確認。どちらもなければ不許可 |
| 本格版（次期） | 王手の連なりを2〜3手読み、詰む応手の割合で勝負手を判定。詰探索と統合 |

**設計上の注意**
- 「取るだけの王手」が次の勝負手の準備になるケースがあるため、許可条件は1〜2手先の王手まで広げられる構造にする。
- 王手全般に減点はしない（王手飛車取りが壊れるため）。
- 「負けが確定した局面」の判定には依存しない（全局面で許可制を適用する）。

**受け入れ基準**
- 例①②の局面を再現した回帰テストで、王手を連発したら失敗とする
- 王手飛車取り・詰みに繋がる王手は許可される
- 上記テストは、テスト局面集の**最初のケース**とする

### 4.2 手数を伸ばす（詰まされるまでの粘り）
- 負けの局面では、詰みまでの手数が長い手を好む（`-MATE + ply` の素直な形）。
- ただし手数を伸ばす手段は、逃げる・守る・合駒など**王手以外**。
- 理由：初心者は三手詰が読めない。手数を伸ばして一手詰に近づける指し方は、初心者もしない。

### 4.3 駒への愛着（王より飛車）
- 王の価値は評価値に入れない（詰みは探索側で別処理）。
- 飛車が相手の利きにあり逃げ場が少ない局面を、大きく減点する別項として持つ。盤面が悪化しても飛車を逃がす手が選ばれる。
- 調整するつまみ：「飛車を守る項の重み」「自玉の詰みを読む深さ」。

### 4.4 定跡をなぞる
§8を参照。囲い（美濃・矢倉）を、状況に合わなくても組もうとする挙動を含む。

### 4.5 投了しない
- 詰まされるまで指す。投了ロジックは持たない。
- 理由：初心者は三手詰が読めず、互いに気づかない可能性があるため。

### 4.6 得意パターンは深く読む（将来）
- 美濃崩しなどよくある型の長手数の詰みは、深さに関係なく読める。
- 実現には詰みパターン辞書が必要。MVPの対象外。ただし§4.1本格版と同じ詰探索基盤の上に載せる前提で設計する。

### 4.7 見落とし（認知の癖）
- 対象は**遠くにある飛車・角（成り駒の馬・竜を含む）の利き**だけ。それ以外（目の前の駒、近い利き、取り合いの収支）は見落とさない。人間の級位者が見落とすのはここで、既存の将棋AIは逆に目の前も見落とす。
- 頻度は**1手あたりではなく1局あたり**で決める。対局開始時に「この局で見落とす回数」を抽選する。**1局あたりの最大回数**を上限に持つ（確率が低くても、1局に致命的な見落としが何度も出て将棋として成立しない状態を防ぐ）。
- 初期案（体感で調整）：一般には6級で1局に1回、3級で5局に1回と言われる。毎局では不自然なので、6級でも数局に1回（約1/3局）、3級は約1/5局から始める。
- 数えるのは「実際に手が悪くなった」見落としだけ。見落としても選ぶ手が変わらない場面では数えない。
- 角は飛より見落としやすく、距離が遠いほど見落としやすい（初期案）。
- 酒に酔った状態のような乱調は入れない。ブレは級と棋風の範囲で作る。
- 自己対局で「N局中M局で有効な見落とし」を集計し、設定値とのズレを確認する。
- 設計の判断は DECISIONS D-014。

## 5. 棋風とペルソナ

### 5.1 軸
- **攻守**：攻めっ気が強い／守り傾向
- **戦法**：居飛車党／振り飛車党／変態党（鬼殺し含む）
- 組み合わせ可能（例：攻め×居飛車）。

### 5.2 制約
- **居飛車党と振り飛車党は排他**（両立しない）。
- 振り飛車は評価だけでは序盤に振らないため、定跡と併用する。

### 5.2.1 キャラと棋力は独立に選ぶ
- キャラ = 特性（攻め屋気質・居飛車党など）の組み合わせ。棋力（級）は別に持ち、同じキャラで級を選べる（D-012）。
- 級ごとの既定値（そのキャラの標準の級）を持ってよいが、固定ではない。

### 5.3 攻め屋の評価設計（初期案）
- 位置価値テーブル（PST）を前進寄りにする。駒の素点は少し下げる。成駒に大きなボーナス
- 敵陣（1〜3段目）の制圧度：自駒の利き数−敵駒の利き数。**玉の位置に依存しない**
- 飛車の走る筋に重み（筋の突破）
- 攻め駒（敵陣周辺の自駒＋持ち駒）の数に小さなボーナス（後続を用意する）
- 手を渡さない傾向：自陣方向への後退に小ペナルティ。持ち駒温存への小ペナルティは最後に、弱めに
- 王手そのものは評価しない（無謀な王手魔になるため）

### 5.4 囲い（目標と評価）
- 囲いは形ごとに硬さ（pt）を持ち、SFENの盤面と一致したかで判定する。戦法と相手の戦法ごとに「ゴール」を持ち、ゴールの先は係数で弱く引く（データは `src/eval/castles.js`、判断は DECISIONS D-018・D-019）。
- 組み上げの順は定跡が主役。評価は、定跡を外れた後に組んだ形を崩さないための保険。
- 向かい飛車は、級が上がると片美濃で満足する（6級＝美濃、3級＝片美濃）。級のデータでゴールを上書きする（Phase 5）。
- 形は10形に絞った。増やす前に測る（評価で囲いを細かく作るほど、指し手を縛る害が大きい）。

## 6. 評価関数の構造

```
score = 駒得 + Σ ( style.係数_i × 項_i(局面) )
```

- 係数は `style.weights`（`{項id: 重み}`）に外出し。ペルソナ＝「特性の組み合わせ（＋微調整の重み）」（D-012）
- 項は部品化（`eval/terms/`）して `eval/registry.js` に登録する。項は素の値を返し、重みは評価関数が掛ける（D-013）
- 特性は `characters/traits/`、ペルソナは `characters/personas/` に1ファイルずつ置く（どちらもロジックを持たない純データ）
- 項ごとの寄与を出力できる（なぜこの手を選んだかを追える）
- 評価値は手番側視点（negamax）
- 人間の格言（王より飛車、馬の守りは金銀三枚 など）は、素点ではなく**状況つきの評価項**として実装する（DECISIONS D-011）

## 7. 探索と指し手の選択

### 7.1 探索
- αβ探索（negamax）、静止探索、反復深化、手の並べ替え、置換表（Phase 2）
- 探索は全ペルソナ共通。評価関数を引数で差し替える
- 静止探索の確認用テスト：▲4五歩に対する9手交換のような、取り合いの収支が分かる局面

### 7.2 指し手の選択ルール（人間らしい発散）
1. 最善手との評価差が `margin` 以内の手だけを候補にする
2. 候補を順位別の重み、または評価差に応じた重み（softmax）で抽選する
3. 一定確率（`slip率`）で、広い margin から選び、稀な悪手を出す
- つまみ：`margin`、重み、候補数、`slip率`。棋力帯とペルソナで変える
- 注意：αβは最善手以外の評価値を正確に返さないため、ルートの各手を個別に探索する（MultiPV方式）
- 王手は§4.1の許可制を通した上で候補にする

### 7.3 手数・ルール
- 最大手数（例：300手）で引き分け打ち切り
- 千日手・連続王手の千日手は、tsshogiの対応範囲を確認し、足りない分は盤面ラッパーに実装

## 8. 定跡

**目的**：「一直線棒銀などの典型的な攻めに、人間の初心者らしく対応できる序盤」を積むこと。強いエンジンの指し手を再現・蒸留した定跡集を作ることではない。

### 8.1 格納形式
- **局面キー → 候補手と重み**。手順ではなく局面で持つ（手順前後でも合流できる）
- 局面キーは**盤面・持ち駒・手番**を含む。持ち駒が違えば別局面なので、持ち駒を打って合流することは起きない
- 各候補に付けるもの：タグ（棒銀受け、美濃囲い等）、ハメ手回避フラグ、ペルソナ別・棋力帯別の重み上書き

### 8.2 選択
- 重みに従って確率選択（乱数はシード固定可能な関数に一本化）
- 例：後手振り飛車党の▲7四歩△3六歩▲2四歩に対し、△4六歩60%／△3五歩20%／△4二飛5%／△3二金5%／△8八角成3%…
- 定跡から外れたら、評価関数＋探索に切り替える。外れた後も、棋力帯に応じた確率的な発散を許す
- 多少下手な定跡もあえて入れる。ハメ手は定跡として回避させる

### 8.3 制作
- 定跡データは自作（既存の公開定跡は強すぎ、初心者像に合わない）
- 量が膨大になる前提で、KIFから取り込むスクリプトと重みの一括編集手段を用意する
- 最大の作業量になる可能性がある

### 8.4 アクセス境界
- 定跡の参照は `book.lookup(局面) → 候補手と重み` の1関数に閉じ込める（将来のAPI化に備える）

## 9. 再現性と乱数

- `Math.random()` を直接使わず、シード付き乱数に一本化
- テスト・自己対局：シード固定で再現
- 本番：シードを毎回変える（ハム将棋の「同じ棋譜で勝てる」問題の解消）

## 10. 棋力調整

- 調整つまみ：探索深さ、ノード数、静止探索の有無、`margin`、`slip率`、定跡の発散度
- 弱くするときは「強いAIを弱くする」のではなく、「偏った浅読みAI」を先に作り、浅さは後から調整する
- 校正：ぴよ将棋との対局勝率（目標4〜6割）。級と設定値の対応表を残す
- 自己対局で、ペルソナ間の勝率と棋風の違いを確認する

## 12. 技術・環境

- 言語：JavaScript（Node.jsで開発・検証、最終的にHTML/CSS/JSでブラウザ動作）
- ルール：tsshogi（MIT）。薄い窓口（`legalMoves / makeMove / unmakeMove / isGameOver` ＋ 評価用 `pieceAt / hand / turn / inCheck`）を挟む
- 公開：まずGitHub Pages。探索はWeb Workerで動かす
- ハメ手対策データが公開リポジトリで読める点は、初期は許容。必要になったら、盤面を受け取り指し手を返すAPI（Cloudflare Workers等）へ移行
- 開発：Git管理、`node --test`。実装はAIに一気に作らせ、コミットで戻れる状態にする
- 性能目標：スマホで1手あたり数秒以内（要確認）

- 定跡の最初の収録範囲（まず何戦法×何手まで作るか）
- 入玉・持将棋のルール扱い
- UIの最初の形（USI対応か簡易HTMLか）
- スマホの性能目標の具体値
- 成駒の係数（`kyuui` は仮置き、青野理論には成駒の値がない）。ぴよ将棋との対局と定性チェックで見直す
- 格言項（馬の守りなど）の加点の大きさと、「自陣・守備に利いている」の判定方法
- 見落としの具体値（級ごとの確率・最大回数、飛と角の差、距離の閾値）。体感と自己対局の集計で調整する（§4.7）

## 15. 進め方（概要）

1. **Phase 0〜1**：盤面ラッパー、駒得αβ、自己対局、棋譜出力、シード付き乱数
2. **Phase 2**：静止探索、反復深化、置換表。**無駄王手排除（簡易版）とテスト局面1〜4を入れる**
3. **Phase 3**：攻め屋ペルソナ、指し手選択ルール（margin／slip）
4. **Phase 4**：人間らしさ。**共通ルール：新機能は「測る指標・OFFスイッチ・ON/OFFの自己対局比較」の3点セットで入れる（D-017）**
   - **4-0 物差し**：評価項ごとの寄与の測定（平均・最大、駒得との比）と control/advance の再調整、対局ランナー（A対B、先後入替、開始局面をばらす）、棋風の率テスト、局面6を深さ2以上の飛車逃げ明示テストに強化、retreat を `selection` に接続
   - **4-1 定跡基盤**：手順→局面キー表のビルド、lookup、出口局面の検査（D-016）。範囲はまず一直線棒銀に対応できる程度（D-006）
   - **4-2 戦法特性**：居飛車／振り飛車、飛車位置の項、囲いの項（D-015）。検証は、定跡オフでも10手後に飛車が5〜8筋にいる率
   - **4-3 受けとハメ手対策**
   - **4-4 詰み探索**：別ルーチン、パターン合致時のみ
5. **Phase 5**：級のデータ（`characters/levels/`）、見落とし（§4.7、D-014）、`createPlayer`、棋力校正（ぴよ将棋）、ペルソナ追加と組み合わせ。見落としの集計は4-0の対局ランナーで取る
6. **Phase 6**：定跡量産、詰探索の拡張（勝負手・パターン辞書）、USIまたは簡易UI、公開と演出
